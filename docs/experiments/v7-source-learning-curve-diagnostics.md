## 结论先行

- 两个 64-source ordering 的 source 集合完全相同，训练窗口/特征身份、标准化和
  source/class 权重也相同；代码按 support 文件顺序筛选训练行，未按 ordering
  清单重排 batch。保存记录都来自 CUDA，状态最大绝对差异随模型 seed 为
  `0.2229 / 0.000356 / 0.00922`，而旧记录没有保存 CUDA 确定性设置，因此不能
  把两者差异解释成第二次独立 source 抽样或确定的 ordering 方法效应。
- 64-source 的训练 replay source-macro AUROC 为 `0.647/0.648`，验证为
  `0.635/0.643`（两个 ordering）；训练没有明显高于验证的普遍性，因此当前
  证据不支持“拟合很好但跨 source 崩溃”为唯一主因。
- 验证规模扩大仍有改善倾向：32→64 的 source-macro 配对差为
  `+0.063 [−0.087, 0.222]`（ordering 20260909）和
  `+0.087 [0.008, 0.183]`（20260910）。32→16 分别为
  `+0.175 [−0.056, 0.397]` 与 `−0.008 [−0.119, 0.095]`，说明小规模结果
  对 source 组合敏感。
- 所有模型都记录了 200 个 epoch，loss 没有 NaN/Inf；64-source 最后五个 epoch
  仍下降约 `0.00051`。这只说明仍有轻微优化变化，不能单凭 loss 断言继续训练
  会改善留出 source。

## A–D 证据判断

- A 训练尚不充分：有轻微的末段下降，但没有仅凭已有记录确认延长 epoch 会提高
  留出表现。
- B source 覆盖不足：得到最直接的支持。验证曲线整体从 8/16 向 32/64 上升，
  且小规模 ordering 差异明显；区间仍宽，不能宣称稳定泛化。
- C 表示/聚合有限：仍未排除。64-source 训练 replay 也只约 0.65，表明当前
  表示在训练 source 上并非接近完美。
- D 训练拟合好但跨 source 不足：不作为首要解释；64-source 的 train/validation
  macro 接近，而不是典型的大训练-验证落差。
